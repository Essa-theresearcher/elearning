0. Mindset — rules, not magic

Programs make decisions the same way a guard at a gate does: look at the facts, apply the rule, then allow one action. Python does not “guess” what you meant — it only runs the lines whose conditions are true.

Step-by-step: turn a real rule into code

  1. Write the rule in English. Example: “If the student is 18 or older, allow entry; otherwise say they are too young.”
  2. List the facts you need. Here you need one number: age. Decide where it comes from (fixed in code for practice, or input() later).
  3. Underline the test. “18 or older” → age >= 18. That expression becomes True or False.
  4. Write the action for when the test is true. Indented under if: e.g. print("Enter").
  5. Write what happens when the test is false. Use else: and indent the other action.
  6. Run with three test values (17, 18, 25) and confirm output matches your English rule.

Why this order matters: Students who skip steps 1–3 usually type if with the wrong comparison or wrong indent. Professionals always nail the sentence first.

Your notebook: Title a page “English → Python”. Every program this week starts with one English sentence on that page.

1. Comparisons → True or False

A comparison asks a yes/no question. Python answers with the boolean values True or False (capital T and F). Those booleans are what if uses to choose a branch.

age = 20
print(age >= 18)   # True  — question: "Is age at least 18?"
print(age == 17)   # False — question: "Is age exactly 17?"
print(age != 20)   # False — question: "Is age different from 20?"
OperatorQuestion it asksExample
==Are these equal?score == 100
!=Are these different?status != "closed"
< > <= >=Order on a number linemark >= 50

Step-by-step: read one comparison line

  1. Find the variable’s current value (from earlier assignments).
  2. Read the operator as a question in English.
  3. Answer yes → True, no → False.
  4. If the line is print(...), that boolean is what gets shown (Python prints True/False).

= vs == (memorize this): A single equals stores a value: age = 20. Double equals tests equality: age == 20. Writing if age = 20: is illegal — Python will show SyntaxError because it expected a condition, not an assignment.

Predict set A — work on paper, step by step

  1. x = 10 then print(x > 5) — Step: Is 10 > 5? → True.
  2. x = 10 then print(x = 5) — Step: this is assignment inside print → SyntaxError (no running needed if you spot = vs ==).
  3. a = "10" then print(a == 10) — Step: text "10" is not the number 10 → False.
  4. balance = 0 then print(balance == 0) → True.
  5. name = "Ali" then print(name == "ali") — Step: Python compares letters exactly → False (case matters).

Only after you write your answers, type the five snippets in VS Code and confirm.

3. if / else — exactly one branch

When you have two outcomes only, use if + else. Python evaluates the condition once; exactly one of the two blocks runs.

score = 55
if score >= 50:
    print("Pass")
else:
    print("Retake")

Step-by-step: what Python does when this runs

  1. Line 1: store 55 in score.
  2. Line 2: compute 55 >= 50 → True.
  3. Because the condition is true, Python runs the indented block under if (line 3).
  4. Python skips the entire else block when if was true.
  5. Change score to 40 and trace again: condition false → line 3 skipped → line 5 runs.

Step-by-step: write your own if/else (template)

  1. Create file decision1.py.
  2. Put the fact on line 1 (e.g. age = 17 or age = int(input("Age? ")) later).
  3. Line 2: if + condition + colon.
  4. Lines 3+: four spaces, action when true.
  5. else: aligned with if, then indented action when false.
  6. Run twice with values that should hit each branch.

4. Indentation — the syntax of decisions

Python has no curly braces { }. The colon after if starts a block; the indent (usually four spaces) tells Python which lines belong to that block.

if True:
    print("A")   # inside if
    print("B")   # inside if
print("C")       # outside if — ALWAYS runs

Step-by-step: read indentation

  1. Find the line with if / elif / else — note its indent level (column 0).
  2. Any line indented more than that belongs to the block until indent returns back.
  3. Lines at the same indent as if are siblings — they run after the whole if/else finishes.

Fix-it drills 4.1–4.5 (method)

  1. Copy the broken snippet into indent_fix.py.
  2. Run and read the error (IndentationError or wrong output).
  3. Draw vertical lines on paper showing which lines should group.
  4. Fix spaces and colon, run again until correct.

5. elif ladders — grades, tiers, shipping

Use elif (“else if”) when you have three or more outcomes. Python checks from top to bottom and stops at the first true condition.

mark = 72
if mark >= 80:
    grade = "A"
elif mark >= 60:
    grade = "B"
elif mark >= 50:
    grade = "C"
else:
    grade = "F"
print(grade)

Step-by-step trace for mark = 72

  1. Is 72 >= 80? No → skip A block.
  2. Is 72 >= 60? Yes → run B block, set grade = "B".
  3. Python does not check remaining elif lines after one matches.
  4. print(grade) shows B.

Step-by-step: build a grade ladder without bugs

  1. On paper, list tiers from highest threshold to lowest (A first, then B, …).
  2. Write one if for the top tier, then elif for each lower tier, then else for “everything left”.
  3. Never use overlapping ranges without thinking — e.g. >= 50 before >= 80 catches 85 too early.
  4. Test four marks: one per grade band + edge values (80, 60, 50, 49).

Common mistake explained: Student writes if mark >= 50: grade = "C" first. A mark of 90 satisfies >= 50, so they never reach the A branch. Fix: reorder, not rewrite the numbers.

7. and / or / not — real-world gates

and means both facts must be true. or means at least one. not flips True↔False.

Step-by-step: login with AND (secure pattern)

  1. Store username and password from input (or fixed strings while learning).
  2. English: “Access only if username is admin and password is 9999.”
  3. One condition: user == "admin" and pwd == "9999" — both must match.
  4. else: print denied — do not reveal which part failed (real apps avoid “wrong password” hints to strangers).
age = 16
paid = True
if age >= 18 and paid:
    print("Full access")
elif paid:
    print("Guest pass")
else:
    print("Pay first")

Trace: age 16 → first condition false (not 18+). Second line checks elif paid → True → Guest pass.

9. input() + decisions (Week 2 review)

input() always gives you a string. Before you compare to numbers, convert with int() or float().

Step-by-step: interactive pass/fail

  1. Run program — Python waits at input("Mark? ").
  2. User types 55 and Enter — program receives the string "55", not the number 55.
  3. int(...) converts to integer 55.
  4. 55 >= 50 is True → pass branch runs.
mark = int(input("Mark? "))
if mark >= 50:
    print("Pass")
else:
    print("Retake")

If the user types letters: int("abc") crashes with ValueError. Section 10 shows how to guard that — for now test with numbers only.

10. Validation guards (step-by-step expert pattern)

Guard means: stop early when input is unusable, so the rest of the program does not make wrong decisions.

Step-by-step: validate age input

  1. Read raw text — never convert to int immediately if empty input is possible.
    raw = input("Age? ")
  2. Guard empty: if user pressed Enter only, raw == "" → print message and stop (or use else for good path).
  3. Convert inside the good path: age = int(raw).
  4. Guard impossible values: if age < 0, reject.
  5. Main rule last: adult vs minor only when age is valid.
raw = input("Age? ")
if raw == "":
    print("Age required — please run again and type a number.")
else:
    age = int(raw)
    if age < 0:
        print("Invalid age")
    elif age >= 18:
        print("Adult")
    else:
        print("Minor")

Why nested if here? You only convert to int when you know the string is not empty. Later Week 5 adds try/except for non-numeric text.

11. Nested if — trace outside → in

When a decision depends on another decision, nest an if inside a block. Always evaluate the outer condition first.

Step-by-step trace (admin example)

  1. User types role admin → outer if true → enter block.
  2. Program asks for code — second decision only runs because role was admin.
  3. If code wrong → inner else runs; outer else (student view) is skipped entirely.
  4. If role not admin → inner block never runs — do not ask for code at all.
role = input("Role? ")
if role == "admin":
    code = input("Code? ")
    if code == "9999":
        print("Admin OK")
    else:
        print("Bad code")
else:
    print("Student view")

13. Menu programs — mini project (full build steps)

A menu-driven program shows options, reads a choice, then runs one block. This is the same pattern as ATM apps, school portals, and shop kiosks — without loops yet (Week 4 makes it repeat).

Step-by-step: build your first menu (30–45 minutes)

  1. Name the file menu_bank.py and add header comments: your name, date, purpose (“Simple bank menu”).
  2. Print the menu exactly — users must see numbers and labels:
    print("1) Check balance")
    print("2) Deposit")
    print("3) Help")
    print("4) Quit")
  3. Read choice as text: choice = input("Enter option: ") — compare to "1", not 1, unless you convert.
  4. One elif per option — same indent pattern as grade ladder.
  5. else branch for typos: print("Invalid option").
  6. Deepen one option: e.g. Deposit asks amount with input and checks float(amount) > 0 with if/else.
  7. Test matrix: run once per menu number + once with 9 for invalid.
print("1) Balance  2) Deposit  3) Quit")
choice = input("Pick: ")
if choice == "1":
    print("Balance: 1200 KES")
elif choice == "2":
    amount = input("Amount to deposit? ")
    if amount == "":
        print("No amount entered")
    else:
        print(f"Deposited {amount} (demo)")
elif choice == "3":
    print("Goodbye")
else:
    print("Invalid option — pick 1, 2, or 3.")
