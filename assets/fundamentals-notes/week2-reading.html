0. Mindset — names hold values

A variable is a label on a box. The box can hold different values over time; the label (name) stays. Assignment = means “store into the name”, not “equals” in math class.

Step-by-step: trace like Practical Sunday

  1. Write each line number on paper.
  2. After each assignment, write the name and its value in a table.
  3. At print, read the current value — not the old one.
  4. Only then run the program and compare.

1. Variables store values (full trace)

score = 10
score = score + 5
print(score)   # 15

Step-by-step: what happens

  1. score = 10 — box named score holds 10.
  2. score = score + 5 — read score (10), add 5, store 15 back into score.
  3. print(score) — shows 15.

Practice 1.1

Trace on paper then run:

a = 3
b = a + 2
a = 1
print(b)

Answer: b stays 5 because b was set before a changed to 1.

3. Strings vs numbers

"5" is text; 5 is a number. They are not interchangeable without converting.

print("Hello" + " World")   # Hello World
print(3 + 4)                 # 7
# print("3" + 4)             # TypeError

Step-by-step: fix TypeError on +

  1. Read error: unsupported operand types str and int.
  2. Find the + that mixes text and number.
  3. Either convert: int("3") + 4 or use f-string: f"Total: {3 + 4}".
  4. Re-run with same test input.

4. input() always returns a string

name = input("Name? ")
age = int(input("Age? "))
price = float(input("Price? "))

Step-by-step: interactive age in 5 years

  1. Program waits at first input — user types and presses Enter.
  2. Even if user types 17, input returns "17" (string).
  3. int(...) converts to number 17 for math.
  4. future = age + 5 then print(f"In 5 years you will be {future}").
  5. Test: age 10 → 15; age 18 → 23.

ValueError: user types letters into int(input()) — program crashes. Week 3 guards and Week 5 try/except fix this; for now test with numbers only.

5. Conversion cheat sheet (with steps)

  • int("12") → 12 — use for whole counts
  • float("3.5") → 3.5 — money and measurements
  • str(100) → "100" — building messages

Step-by-step: fix-the-bug pattern

  1. Broken: total = input("Total? "); print(total + 1)
  2. Trace: total is str → + 1 fails.
  3. Fix: total = int(input("Total? ")) or float for decimals.
  4. Test with 10 → expect 11.

6. f-strings for receipts and reports

item = "Notebook"
qty = 2
unit = 150
line = qty * unit
print(f"{qty} x {item} = {line} KES")
print(f"VAT 16%: {line * 0.16:.2f}")

Step-by-step: build a 4-line receipt

  1. Ask item (string input), qty (int), unit (float).
  2. Compute line = qty * unit.
  3. Compute VAT: line * 0.16.
  4. Print header, line item, VAT, grand total with f-strings.
  5. Test: qty 2, unit 100 → line 200, VAT 32, total 232.

.2f formats two decimal places for money display.

7. Operators — math and assignment

count = 0
count += 1    # same as count = count + 1
total = 10 * 3 + 2   # 32 — * and / before +

Step-by-step: read an expression

  1. Do multiplication/division first (unless parentheses).
  2. Then addition/subtraction.
  3. Store result in variable on left of =.

13. Debugging checklist

  • TypeError on + → mixed str and int/float? Convert or f-string.
  • ValueError on int(input()) → non-numeric input; use valid test data.
  • Wrong math → print debug: print("debug qty", qty) before total.
  • Wrong output order → trace assignments top to bottom.
