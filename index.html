    Welcome to Computer Fundamentals

    The missing layer behind the Python you already know.

    You have learned Python basics: variables, loops, functions, and maybe a few small projects. This lesson fills the layer underneath that work: what is happening inside the machine when your code runs.

    • A clear mental model of the four core hardware components inside any computer.
    • How data becomes patterns of 1s and 0s, and how encoding turns those patterns into meaning.
    • What happens between starting a Python script and seeing output on screen.
    • How Python stores variables in memory, and why references and mutability matter.
    • How the operating system juggles many programs on limited hardware.
    • A hands-on activity that turns the concepts into predictions, observations, and notes.
    • The vocabulary to explain this clearly in interviews, reviews, and debugging.

    1. What Is a Computer, Really?

    Every computer is built from four core parts working together. Understanding them explains why programs run out of memory, why disk access feels slow, and why some tasks are CPU-bound while others are I/O-bound.

    Component Job Analogy
    CPU Executes instructions, one at a time. The chef doing the cooking.
    RAM Holds data the CPU is actively working with. The kitchen counter: fast, but cleared later.
    Storage Holds files permanently, even when powered off. The pantry: slower to reach, but persistent.
    I/O Moves data in and out through keyboard, screen, network, and disk. Waiters carrying orders in and dishes out.
    Quick check: Your saved Python file does not disappear after shutdown because it lives in storage. It is only loaded into RAM while the program is running.

    2. Everything Is Just Numbers: Binary

    At the lowest level, a computer recognizes two electrical states: on and off. We represent them as 1 and 0. Text, photos, numbers, and Python scripts are ultimately long sequences of those bits.

    • Bit: one 1 or 0, the smallest unit of data.
    • Byte: 8 bits, enough for 256 possible values from 0 to 255.
    • Encoding: a rule for turning bytes into meaning, such as text.
    >>> ord('A')
65
>>> bin(65)
'0b1000001'
>>> chr(65)
'A'
>>> ord('a')
97

    ASCII covers basic English letters, digits, and punctuation. Unicode expands this to cover writing systems such as Somali and Arabic, plus symbols and emoji. Python 3 strings are Unicode by default.

    3. From Your Code to a Running Program

    Readable Python has to be transformed before the CPU can execute it. The journey is source code -> interpreter -> bytecode -> Python Virtual Machine -> machine code and CPU.

    Question Compiled languages Interpreted languages
    Before running Translated to machine code ahead of time. Translated to bytecode as it runs or just before.
    Speed Generally faster at runtime. Generally slower because translation is part of execution.
    Flexibility Must rebuild after many code changes. Run immediately after a change, useful for fast iteration. 
    import dis

def add(a, b):
    return a + b

dis.dis(add)

    4. How Python Stores Variables

    In Python, a variable is a name pointing to an object in memory. It is not a labeled box that holds a value. This is why assigning one list to another name can make both names point to the same list.

    a = [1, 2, 3]
b = a
b.append(4)
print(a)  # [1, 2, 3, 4]

    == checks whether values are equal. is checks whether two names point to the exact same object. Lists, dictionaries, and sets are mutable; integers, floats, strings, tuples, and booleans are immutable.

    Prediction exercise: Work out what x = 10; y = x; y = y + 5; print(x, y) prints before running it. Then explain why numbers behave differently from lists.

    5. The Operating System's Role

    The operating system decides which process gets CPU time and for how long. It switches between programs so quickly that many tasks feel simultaneous even when hardware is limited.

    • Process: a running instance of a program with its own private memory.
    • Thread: a smaller unit of work inside a process; threads share memory.
    • Scheduling: the OS choosing what runs next.
    • Context switching: saving one process state and loading another.
    • GIL: CPython's lock that allows only one thread to execute Python bytecode at a time.
    Full journey: You type Python source -> the interpreter turns it into bytecode -> the OS creates a process and loads it into RAM -> the CPU executes instructions -> output appears and can be saved to storage.
