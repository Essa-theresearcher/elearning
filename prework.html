    Reading

    The Python intermediate skills map

    Use this map before the quiz and coding review. It defines what "intermediate Python" means for this course.

    1. Intermediate means you can reason, not just remember syntax

    In this course, an intermediate Python learner does not need to know every library or every shortcut. You do need to understand how a small program moves from input to processing to output. If you see a block of Python code, you should be able to say what each part is responsible for.

    A useful test is this: can you change a working example without breaking the whole thing? If the answer is yes, you are probably ready for faster lessons. If every small change feels mysterious, spend more time with the fundamentals before rushing.

    2. The baseline toolkit

    An intermediate Python learner should be comfortable with:

    • Variables, strings, numbers, booleans, and basic type conversion.
    • Conditionals such as if, elif, and else.
    • Loops over lists, strings, or dictionary items.
    • Functions that accept inputs, return values, and avoid repeated code.
    • Lists and dictionaries for organizing related data.
    • String methods, slicing, and formatting.
    • Basic classes, objects, attributes, and methods.
    • File reading/writing with with open(...).
    • List and dictionary comprehensions.
    • try/except error handling and reading tracebacks.

    3. Debugging is part of the assessment

    The coding review is allowed to contain mistakes while it is being built. What matters is whether you can isolate the problem. Good debugging sounds like: "This function receives a list, but I passed a string" or "The loop works, but my condition is too broad."

    Weak debugging sounds like: "It does not work" with no attempt to locate where. The course will teach deeper ideas, but you need enough patience and structure to investigate small failures.

    4. What to do with the result

    Use the quiz and project together. A high quiz score with a weak project may mean you recognize concepts but need more practice applying them. A modest quiz score with a strong project may mean you can build but need vocabulary review. The project reflection is important because it shows how you think. 

    Readiness decision:
- Ready: quiz is solid, project runs, explanation is clear.
- Almost ready: project is incomplete but reasoning is visible.
- Needs foundations: cannot explain code, no working project, or no debugging evidence.

    5. How to use your readiness result

    Use the auto-scored quiz and the coding review together. Multiple choice can show recognition, but the open-ended prompts show whether you can actually write Python in a small realistic task.

    • Ready: strong quiz score, working code, and clear explanations of choices.
    • Almost ready: understands basics but struggles with OOP, comprehensions, file I/O, or error handling.
    • Foundations first: weak control flow, weak functions, no debugging evidence, or copied code without explanation.

    6. Practice drills before the coding review

    Before submitting the coding review, you should be able to do these in your own editor:

    • Write a function that accepts a list of numbers and returns the average.
    • Loop through a dictionary and print formatted summary lines.
    • Use a list comprehension to filter values from a list.
    • Create a small class with an initializer and one method.
    • Read text from a file or explain exactly how with open(...) works.
    • Use try/except to handle a bad input cleanly.
